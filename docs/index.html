Primeros pasos

Instala el SDK

Un único paquete en cualquier proyecto NestJS. Sin agentes, sin configuración de infraestructura.

terminal
bun add @angelitosystems/nest-devtools
# npm install @angelitosystems/nest-devtools

Primeros pasos

Tu primera sesión de debugging

Agrega una línea a main.ts, arranca el servidor y abre el dashboard.

src/main.ts
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';
import { NestDevTools } from '@angelitosystems/nest-devtools';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  NestDevTools.init(app);
  await app.listen(3000);
}
bootstrap();

Características

Qué captura DevTools

Requests

Método, URL, status, duración, query, IP y user agent de cada request HTTP — incluyendo 404s y 5xx.

Logs

console.* y el Logger de NestJS, con archivo, línea y contexto. Filtros por nivel y búsqueda.

Errores

Error explorer con stack traces, ubicación de código y agrupación de errores idénticos por huella.

Performance

CPU, memoria, heap, event-loop lag, req/s y percentiles p95/p99 en gráficos en vivo.

Aplicación

Explora módulos, controllers, providers, guards, interceptores y pipes de la app conectada.

Source locations

Cada log y error sabe dónde ocurrió: users.service.ts:87:21, con enlaces a VS Code y Cursor.

Características

El dashboard

  • Overview — tarjetas de estado y feeds en vivo de requests, logs y errores.
  • Requests — tabla buscable con panel de detalle por request.
  • Logs — filtros ALL/DEBUG/INFO/WARN/ERROR, búsqueda y pausa del stream.
  • Errors — agrupados por huella con ocurrencias y stacks.
  • Performance — sparklines de CPU, heap y latencia en tiempo real.
  • Application — el grafo de módulos de tu app.

Configuración

Opciones de inicialización

Todo es opcional — los valores por defecto están pensados para desarrollo local.

src/main.ts
NestDevTools.init(app, {
  server: 'ws://localhost:4318',
  project: 'my-api',
  environment: 'development',

  redact: ['cardNumber', 'cvv'],
  allow: ['publicToken'],

  capture: {
    requests: true,
    logs: true,
    errors: true,
    performance: true,
  },
});

Operación

Seguridad por diseño

Nada sale de tu proceso sin pasar por el motor de redacción: password, token, authorization, cookie, apiKey, secret y derivados se reemplazan por [REDACTED], incluso dentro de texto libre (password=hunter2).

  • Headers sensibles nunca se capturan — solo una whitelist segura.
  • Denylist con coincidencia parcial + allowlist para excepciones.
  • Todo vive en memoria en el servidor — nada se escribe a disco.
  • El dashboard es local (localhost) por defecto.

Operación

Comportamiento en producción

Por defecto el SDK se desactiva solo cuando NODE_ENV=production: sin parcheo, sin sockets, sin timers — overhead cercano a cero. Forzarlo es posible pero no recomendado.

Regla de oro: si DevTools está apagado, tu aplicación NestJS arranca y funciona con total normalidad. Sin errores, sin bloqueos, sin crashes.
